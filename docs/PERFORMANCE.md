# 性能设计说明

> 目标：100k+ 建筑、500k+ 居民、100k+ 车辆下保持 60 FPS。本文解释每项优化**为什么**这样做——预算从哪里来、花在哪里。

## 1. 帧预算拆分

60 FPS = 16.6ms/帧。分配：渲染提交 ≤ 6ms、模拟 tick ≤ 5ms（30Hz，即每帧摊 ≤ 2.5ms）、其余（流式加载/UI/GC 余量）≤ 5ms。所有优化都对着这张预算表做。

## 2. 渲染：draw call 是第一敌人

10 万栋建筑的多边形数并不可怕（盒体建筑 ~30 三角形 × 10 万 = 300 万三角形，桌面 GPU 轻松处理），可怕的是 draw call。**每类建筑一个 InstancedMesh**：全城建筑 7 个 draw call；车辆 1 个；每区块树木 1 个。当前典型帧 < 150 draws。

- **实例缓冲重建而非逐帧更新**（建筑）：建筑集合每秒最多变化几次，重建一个 InstancedMesh 比每帧写矩阵便宜得多；WebGPURenderer 还会缓存实例数与迟加的 instanceColor 属性，重建同时绕开了这两个缓存坑（这是实测踩到的坑：改 `mesh.count` 与后加 `setColorAt` 在 WebGL2 后端渲染旧状态）。
- **车辆走零缩放槽位**：车辆位置每 tick 都变，必须逐帧写矩阵。固定容量 InstancedMesh，未用槽位写 0 缩放矩阵——`count` 恒定，避开同一个缓存问题，且无重建开销。
- **远处不画树**：LOD step≥4 的区块跳过森林。600 区块 × 1 draw 的树在远处是亚像素噪声，砍掉省数百 draws，视觉零损失。
- **地形 LOD + 裙边**：3 档步长（1/2/4），距离阈值 220/480m。裙边（边界下沉环）遮住相邻 LOD 裂缝，比顶点缝合便宜一个数量级且无视觉差异。
- **视锥剔除**：地形/树按区块粒度由 three 自动剔除（包围球即区块大小）；跨全城的 instanced 大网格禁用剔除（永远可见，剔除计算反而浪费）。
- **后处理走 TSL**：Bloom+FXAA 用 three 的节点后处理，同一份代码在 WebGPU 与 WebGL2 后端都能跑，不为兼容写两套。

## 3. 模拟：错峰 + 稀疏 + 数据导向

- **SoA TypedArray 组件**：热数据（位置、经济数值）连续内存线性扫描，5 万实体的全量遍历 <1ms。这也是查询增量维护（O(变更) 而非 O(实体)）之外的第二道保险。
- **重系统错峰**：电网 45 tick 一算（相位 7）、水网 45（相位 23）、环境场 90（相位 31）、人口 60（相位 47）、垃圾 90（相位 59）、消防 240（相位 101）。任意单 tick 最多承载一个重 pass，帧时间平稳无尖峰。
- **稀疏环境场**：污染/噪音/地价/治安是 32m 格的稀疏 Map，只在有排放源的地方存在。全量重建（每 3s）成本 ∝ 城市大小而非地图大小——无限地图的必要条件。
- **电/水网用连通分量而非流网络**：union-find O(E α(E))，比真实潮流计算便宜几个量级，而玩法语义（分区供电、超载停电）完全一致。

## 4. 交通与代理

- **寻路在 Worker**：A* 与流场跑在 path.worker，主线程只收发消息。路网镜像在版本变更时全量同步（路网变更是低频玩家操作），拥堵权重每秒推送一次。
- **拥堵反馈进成本**：cost = length/speed × congestion。堵车自动让路径规划绕行，这比任何"避让 AI"都便宜且涌现真实。
- **流场为通勤准备**：一次 Dijkstra 泛洪给所有节点最优下一跳，万级代理去同一目的地时 O(1)/代理，替代万次 A*。
- **代理抽象比 1:2**（可调 AGENT_SCALE）+ 硬预算上限：统计模拟承载"50 万人口"的数字真实，代理层承载可见的通勤/交通行为——与 CS1 同款设计，这是在浏览器达成 50 万人口的唯一现实路径。
- **代理 LOD**：远离相机的车辆每 5 tick 积分一次（dt×5 补偿），轨迹一致，CPU 1/5。
- **跟驰用每边占用快照**：每 tick 按 (edge,dir,lane) 分组排序，"前车距离"是邻居查找而非 O(V²) 两两检测。

## 5. 内存

- 实体句柄 u32（世代+索引），签名 32B/实体：100 万实体的 ECS 骨架 <70MB。
- 地形不存网格：种子 + 稀疏编辑增量。存档因此是 KB 级，加载 = 重新生成。
- 对象池（ObjectPool）备好给路径节点等热点分配；当前剖析未显示 GC 压力，未过早启用。

## 6. 已知的下一步（剖析驱动，不提前做）

- WebGPU compute 遮挡剔除（当前场景 draw 数低，收益未显现）。
- WASM 版流场/A*（当前 Worker JS 版在 10k 节点网格 <5ms，未到阈值）。
- SharedArrayBuffer 把 Transform 环形缓冲共享给渲染线程（当前主线程模拟 ~2ms/tick，未到阈值）。
- 纹理图集 + 建筑立面细节（美术阶段）。
